# First-Chapter intro (#100)

R1's `FirstChapterIntro` is a presentational Server Component. Required props are `bookTitle`, `chapterTitle`, `questionCount` and `startHref`. R6 resolves those from the actual immutable Chapter Version and its matching Chapter Check, and owns the authenticated app mount/open flow (comms0056). `startHref` must be a real navigation destination that follows the existing Book-open flow; do not pass a POST API URL or manufacture a Version ID. The component adds no routes, storage, network calls, grading or completion state. Gatsby can be a full Chapter: the copy promises small reading parts, never a short total duration.

R6 agreed account-wide eligibility: no completed Chapter in any Book (`chapter_completions`), resolved server-side. Opened/failed/unfinished reading does not count as completion. The intro can therefore appear on retries until the first real completion, independently of the once-device Welcome splash flag. No dismissed flag, localStorage progress or placement diagnosis is invented here. R6's planned `getFirstChapterIntro(readerId, bookId)` returns real metadata or null without recording progress; actual opening still follows the existing API. Its `versionId` belongs to the mount's resolution/navigation work and is not displayed or duplicated as a separate unused component prop.

No real duration estimate is currently supplied by that seam, so the UI says to take as long as needed rather than inventing minutes. A timed estimate can be added when the data owner supplies a real estimate. The actual question count is shown, including singular wording for one question. Read-aloud is explicitly optional and silent reading remains available. Original book artwork is inline SVG; no new motion or asset dependency.

Keep #100 open until R6 mounts the real eligibility/open flow and the deployed first/returning Reader journey is verified. Isolated component verification cannot establish auth, account eligibility or progress persistence.
