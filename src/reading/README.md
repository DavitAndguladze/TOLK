Demo playback is disclosed before Start: "Play demo" / "Resume demo", with a note that words advance automatically and the microphone is not used. Completed demo results remain explicitly simulated. Real-engine mode keeps the Read aloud / Resume labels and connection/error handling.

Reading aloud stays optional. The opening choice explains that it helps grading accuracy; the Chapter Check slot remains reachable through silent completion or explicit continuation after a failed save (request 0027).

Current-attempt handoff (0024): R4's client ChapterCheck can import `useConfirmedReadAloudStartedAt` from `@/reading/ChapterReadAloud`. The slot is already inside its provider. The hook returns this completion's summary.startedAt only after the save acknowledges success, otherwise null (silent/no-score, failure/Continue, or outside the provider). Retry clears confirmation; inactive requests cannot publish a timestamp. R4 owns the separate ChapterCheckAnswers contract and copying the value into the submission, plus server-side matching/idempotency. The context alone does not fix stale-summary grading; no src/types or R4 files are changed here.

R5 client-parent seam (requests 0008/0023): optional `onWordTap(token: Token, chapterVersionId: string): void` and `flaggedTokenIndexes?: ReadonlySet<number>`. A supplied callback makes words native keyboard-accessible buttons while ready, paused or silent; listening renders noninteractive spans. Without a callback, words remain spans. Flags use a gold background/ring plus screen-reader text without replacing read-aloud miss marks. R5 can wrap ReadingScreen in a client component, supply `useFlaggedWords(chapterVersionId)`, keep the selected token locally, and render its WordSheet keyed by token.index. The current parent is `src/app/read/[versionId]/page.tsx`; it is a Server Component, so pass serializable reading props/Chapter Check slot to the client wrapper, not a server-created callback. Mounting that wrapper needs the src/app owner's review; R2 has not edited R5 or app files.

The ReadingScreen uses `createListeningSource()` from `@/listening/client`, honoring the existing NEXT_PUBLIC_LISTENING_ENGINE build flag. Default mock playback is labelled “Demo listening”; real engines show “Connecting…” until Start resolves, then “Listening”. No automatic engine fallback is added.

`createReadingAttempt({ id, tokens }, source)` wraps the existing ListeningSource for one Reader attempt. Completed-Chunk or Pause summaries are committed once. A new Start waits for the previous Stop; Stop cancels a queued resume. `finish()` awaits cleanup, merges fragments across every Chapter Version token with R1's helper, and returns null for no scored evidence. Recognition partials are never appended as separate fragments. A reread clears old marks only after new scored evidence arrives; failed starts preserve previous results.

The reading reducer clears earlier outcomes on pending revisions and moves the current highlight back when necessary. Pause and Finish preserve unread words as pending. Chapter completion still leads to R4's Chapter Check.

Before the Chapter Check opens, `ChapterReadAloud` confirms the existing POST `/api/chapter-versions/[versionId]/read-aloud` contract. It sends the full merged summary with same-origin credentials and the existing `tolk-reader-session` / X-Reader-Session convention shared by ChapterCheck and WordSheet. R6 owns authentication and Reader + Version persistence. HTTP success plus JSON `{ ok: true }` is required to say saved; the request times out after ten seconds. No audio is sent or stored by this UI.

Silent reading skips the save entirely. If a save cannot be confirmed, the Reader can retry or choose Continue to Chapter Check. No saved-results claim is made in that path. Until R6's route lands, the current dev 404 follows this same visible recovery path, rather than blocking the Chapter Check or pretending to save. R4 still determines the grading basis from actual server state.
